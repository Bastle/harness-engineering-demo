## 3. 讨论的核心概念

### 3.1 feature_list.json 使用原则

- **粒度**：一个任务 = 一个可验证的行为
- **验证命令**：必须可自动执行（npm test、curl、ls），不能是"看看对不对"
- **WIP=1**：同一时间只能有一个 in_progress
- **不可删除**：已完成的任务是历史记录，标记为 passing 而非删除
- **ID 命名**：F01、F02 格式，简洁有序
- **任务拆解**：通过 `tasks` 字段实现子任务，拆到每个子任务都能写一行验证命令为止
- **膨胀控制**：已完成任务归档到 `archive` 数组，或超过 15 个时分组到目录

### 3.2 PROGRESS.md 使用原则

- 记录"此刻的状态"，不是"过去发生的事"
- 变更日志用 git log 替代，不要重复记录
- 不超过 80 行，定期精简
- 每次会话结束时更新，每次会话开始时读取

### 3.3 AI 拆解任务

- 你负责"要什么"，AI 负责"拆成什么"，你负责"对不对"
- 拆解质量靠人工审核，不要让 AI 自己定义"完成"的标准
- 粒度判断标准：能不能写出一行验证命令

### 3.4 确保 AI 代码质量的三层防线

| 防线 | 管什么 | 实现方式 |
|------|--------|----------|
| 验证命令 | 能不能跑 | feature_list 的 verification 字段 |
| 人工验收 | 跑得对不对 | dev-semi.js 每个任务后暂停 |
| 验收标准前置 | 做没做完 | 开工前说清楚具体要求 |

### 3.5 Workflow 设计

- **AGENTS.md 流程** = 员工手册（"你应该怎么做"），AI 尽量遵守但不保证
- **JavaScript Workflow** = 自动化流水线（"机器替你做"），确定性执行
- **Makefile 编排** = 工具无关的 DAG 任务调度，任何 AI 工具都能用
- **半自动模式** = AI 拆解 → 人工审核 → 逐个执行+验收，最实用的起步方式

### 3.6 各工具对比

| 能力 | Claude Code | Codex | Copilot | Cursor |
|------|-------------|-------|---------|--------|
| JavaScript Workflow | ✅ | ❌ | ❌ | ❌ |
| 读 AGENTS.md | ✅ | ✅ | ✅ | ✅ |
| 自主循环 | ✅ | ❌ | ❌ | ❌ |

### 3.7 Claude Code Workflow API

| API | 作用 |
|-----|------|
| `agent(prompt, opts)` | 派一个 AI 做一件事 |
| `parallel([...fns])` | 同时执行多个 agent |
| `pipeline([...tasks], fn)` | 串行执行，前一步结果传给下一步 |
| `phase: 'name'` | 标记当前在哪个阶段 |
| `args` | 接收外部传入的参数 |

这些 API 是 **Claude Code 内置的**，不是 JavaScript 标准 API。
