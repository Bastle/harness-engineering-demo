# 架构决策日志（ADR）

> **为什么需要这个文件？**
> 软件开发中，最难的不是写代码，而是回答"为什么这样写"。
> 三个月后你回头看代码，可能会想："我当时为什么不用 YAML？为什么要做 Makefile？"
>
> 架构决策记录（Architecture Decision Record，ADR）帮你记下每个重要决策的背景、选项和最终选择。
> 这不是给别人看的文档，是给未来的自己看的。

---

## ADR-001：功能清单使用 JSON 而非 YAML/TOML

**日期**：2024-01-01
**状态**：已采纳

### 背景
需要一个结构化的文件来追踪功能任务的状态。候选格式：JSON、YAML、TOML、纯文本。

### 决策
选择 JSON。

### 理由
1. **零依赖**：Python、Node.js、Bash 都能原生解析 JSON，不需要额外安装 YAML/TOML 库
2. **AI 友好**：Claude、GPT 等模型对 JSON 的理解最稳定
3. **可校验**：`python3 -c "import json; json.load(open('file.json'))"` 一行就能验证格式
4. **生态标准**：JSON 是 Web 和 API 的事实标准，读者最熟悉

### 放弃的选项
- **YAML**：更人类友好，但需要额外依赖，且缩进容易出错
- **TOML**：比 YAML 好，但工具支持不如 JSON 广泛
- **纯文本**：最简单，但 AI 解析不够稳定

## ADR-002：用 Makefile 而非 npm scripts 作为任务入口

**日期**：2024-01-01
**状态**：已采纳

### 背景
需要一个统一的命令入口，让 AI 助手和人类都能方便地运行各种任务。

### 决策
选择 Makefile。

### 理由
1. **语言无关**：Makefile 可以调用任何语言的脚本（bash、python、node），不绑定某个运行时
2. **依赖管理**：`check` 依赖 `setup` 和 `test`，Make 天然支持 target 依赖
3. **普遍可用**：macOS 和 Linux 都自带 make，不需要安装额外工具
4. **AI 习惯**：AI 助手对 Makefile 的理解非常成熟，很少出错

### 放弃的选项
- **npm scripts**：只在 Node.js 项目中有用，限制了项目的适用范围
- **shell 脚本**：可以，但没有依赖管理和并行执行能力
- **Taskfile**：更好，但需要额外安装

## ADR-003：分离 CLAUDE.md 和 AGENTS.md

**日期**：2024-01-01
**状态**：已采纳

### 背景
AI 辅助开发工具越来越多（Claude Code、GitHub Copilot、Cursor、Windsurf 等），每个工具有不同的上下文文件格式。

### 决策
维护两个文件：CLAUDE.md（Claude 专用）和 AGENTS.md（通用）。

### 理由
1. **关注点分离**：CLAUDE.md 放 Claude 特有的配置，AGENTS.md 放所有工具通用的规则
2. **避免重复**：如果只有一个文件，每个工具都要读它，但里面混着其他工具的配置
3. **渐进增强**：只用一个工具时只维护一个文件；引入新工具时只需加一个新文件

### 放弃的选项
- **只用 AGENTS.md**：Claude Code 对 CLAUDE.md 有原生支持，不用浪费
- **只用 CLAUDE.md**：其他工具不认这个文件

## ADR-004：每个功能必须有验证命令

**日期**：2024-01-01
**状态**：已采纳

### 背景
如何判断一个功能"真的做完了"？

### 决策
每个功能必须有一个可自动执行的验证命令（`verification` 字段）。

### 理由
1. **消除歧义**：不说"应该能跑了"，而是 `npm test` 通过才算完
2. **AI 可验证**：AI 助手可以自己运行验证命令，不需要人类手动检查
3. **可追溯**：验证通过的证据（evidence 字段）记录在案
4. **防退化**：每次修改后重跑验证，确保没有破坏已有功能

### 核心理念
> **"Done"的定义不是"写完了"，而是"验证通过了"。**

## ADR-005：采用半自动工作流而非全自动

**日期**：2024-01-01
**状态**：已采纳

### 背景
想要实现"输入需求 → AI 自动完成"的全自动开发流程。但全自动的风险在于：
- AI 拆解的任务可能不合理
- 执行中出错没法实时干预
- AI 可能"差不多就行"，不严格验收

### 决策
采用半自动模式：AI 拆解 + 人工审核 + 逐个执行 + 每个任务后人工验收。

### 理由
1. **拆解阶段**：AI 比人快，但可能拆错 → 人工审核
2. **执行阶段**：每个任务后暂停 → 人可以验收、修改、跳过
3. **质量兜底**：人工验收防止 AI "差不多就行"
4. **渐进信任**：随着对 AI 输出的信任增加，可以逐步减少暂停点

### 实现
- `workflows/dev-semi.js`：Claude Code workflow，定义了四个阶段和暂停点
- `AGENTS.md`：定义了通用的工作规则，适用于所有 AI 工具
- `Makefile`：提供了工具无关的任务编排方式

### 未来演进
当对 AI 输出足够信任后，可以：
1. 去掉任务级验收，只保留功能级验收
2. 去掉人工审核拆解，只审核最终结果
3. 切换为全自动 workflow
